# Parola application audit

Reviewed on 3 October 2026 after pulling GitHub main into the local workspace. The audited revision is [bd60180](https://github.com/cmagripp/italianapp/commit/bd60180cc4eea7d9c0bd45e41584048ec752fba1). GitHub main still pointed to that revision at the end of the audit. Its [Pages deployment succeeded](https://github.com/cmagripp/italianapp/actions/runs/37044189794); six sampled production files, including the application entry point, lesson sequencing and service worker, matched the local revision byte for byte.

**Overall evaluation:** Parola has a distinctive, consistent visual identity, a substantial reference library and increasingly capable teaching tools. The latest release improves beginner scaffolding, course vocabulary practice, sentence building and release verification. Its largest remaining weaknesses are the joins between those tools: recommendations, review evidence, completion meanings and saved sessions do not always agree. The course is a useful beginner-to-advanced spine, but its present content and assessment do not yet support the intended comprehensive zero-to-C2 experience.

This is an audit and proposed direction. Application code, lesson data and deployment were not changed. The only new workspace files are this report and its supporting reports. Existing untracked sync copies were preserved.

## Scope and verification

The review covered Home, both Learn views, the course and placement check, grammar lessons, verb and word lessons, Review, all 21 games, Words and search, the reference codex, lists and custom entries, useful words, the sentence workshop, profile/settings, persistence, backup, cloud sync, offline/PWA behavior, optional local models and release architecture. Three parallel specialist reviews examined curriculum, learning integration and system reliability; findings were integrated with independent browser and source checks.

| Check | Result and meaning |
| --- | --- |
| Broad isolated browser suite | 48 of 48 routes and 46 of 46 flows passed; zero console, page or network errors. Some fixtures use the classic lesson mode, so this is broad functional coverage rather than proof of every current taught lesson. |
| Mobile layout matrix | 48 routes × 3 phone dimensions × 2 themes. No reported horizontal overflow, undersized controls under the suite's 40 px rule, undersized input fonts or clipped headings. |
| Layout overlap triage | The raw suite flagged 141 rectangle intersections across 19 combinations. Follow-up checks found intentional card controls, rotated dial bounds, clipped word content and scrollable crossword clues. These are not 141 confirmed UI defects. The last crossword clue remained reachable and tappable after scrolling the internal panel. |

| Course editorial and word help | Selected editorial fixtures passed. The lexicon suite covered 40,123 tokens in 5,457 Italian strings; lookup coverage does not establish prior teaching or retention. |
| Learning and practice checks | Model, integration, completion, verb flow/pacing, short words, course vocabulary boards, workshop, question generation and useful-word suites passed. Additional isolated reproductions exposed review gaps those tests do not currently cover. |
| Storage and optional models | Durability 7/7, learning store/sync 20/20 with mocked network, assistant guards 19/19 with a fake runtime. |

The audit used fresh browser profiles and controlled storage fixtures. It did not use a real cloud account, run the large AI models, measure a physical iPhone's memory or installed-app geometry, perform a full screen-reader/contrast audit, perceptually assess every recording, or independently edit every Italian sentence. Browser emulation cannot certify the earlier iOS Home Screen sizing concern on the physical device.

## What the application now contains

Parola remains a static browser application built with JavaScript modules, HTML and a bespoke CSS/motion system. A service worker supports offline use; IndexedDB stores profiles and evidence, with a localStorage fallback. Optional Supabase sync merges profile data. GitHub Pages publishes a tested build from main. Paid services are not required for the core lessons.

| Area | Current scope | Evaluation |
| --- | --- | --- |
| Main course | 82 units and 256 lessons, Foundations through C2 | A much better guided spine; it needs stronger transfer, skill balance and connection to the rest of the app. |
| Dictionary and codex | 6,958 words, 1,185 verbs, noun forms, usage and conjugation/reference tools | One of the strongest assets. More of this information should be reachable at the moment it helps a lesson. |
| Verb teaching | Five core cases, optional additional forms, progressive forms where appropriate, mixed review | Broad coverage with meaningful completion rules. Pacing and contextual variety vary by verb. |
| Word teaching | Short supported lessons, articles/plurals, matching and recognition | Appropriate for concise vocabulary learning; completion and independent recall need distinct meanings. |
| Course vocabulary | Boards in 86 lessons, 320 board steps and 1,098 pairs in the deterministic suite | A useful bridge from grammar examples to vocabulary; advanced phrases and smaller gloss sets need another practice route. |
| Sentence workshop | 21 lessons and 168 activities across four stages | A valuable move toward using Italian. It currently operates as a separate progression system. |
| Useful words | 78 entries in six groups | Good discovery and targeted practice; should also be introduced within the relevant course units. |
| Games and review | 21 games, entry schedules and skill schedules | Rich practice variety, but inconsistent evidence integration undermines adaptive review. |
| Legacy material | Earlier 129-lesson course and older lesson players | Valuable progress compatibility. Keep it available, while reducing competing learner-facing paths. |

The visual system should largely be preserved. The current typography, glass surfaces, dropdowns, reels, feedback and motion feel related across the app. The next improvement should be clearer hierarchy and shared behavior, rather than another wholesale restyling.

## Confirmed issues to address first

### Review can repeat a resolved difficulty or omit a new one

A game can write an objective such as `w:sempre|adv::word::recall`, while the current word lesson writes different objectives containing `::lesson::`. Review passes the game objective into that lesson, which cannot focus it or update it. In an isolated browser, a game mistake on *sempre* became due; completing the entire linked six-answer review correctly left the original difficulty due with the same timestamp. A verb fixture demonstrated the same identity mismatch.

A separate gap affects games that update only the older entry schedule. Once a word has any adaptive evidence, focused Review suppresses its older due entry even if a fresh game lapse makes it due now and its adaptive skill is scheduled later. The lapse can disappear from Review.

**Recommendation:** establish canonical review destinations and a tested reconciliation rule for all lesson and game evidence. Preserve existing queued objectives through migration. The acceptance test must follow a real game miss through Review and show that the exact difficulty is rescheduled after suitable practice. A separate test must ensure legacy game lapses remain visible, without introducing unlearned verb cases.

Evidence: [question annotation](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/learning/questions.js#L423), [review eligibility](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/learning/integration.js#L123), [lesson focus](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/views/learnJourney.js#L106). The supporting learning report contains the full reproduction.

### Home and Learn disagree about what to continue

In a fresh profile, Home's Continue button opens *credere*, while Learn starts the first Foundations grammar lesson. After starting that grammar lesson and returning to Home, Continue still opens *credere*. Learn correctly resumes the grammar lesson. The Home recommender does not include the same course sessions used by the Learn model.

The workshop saves and resumes within its own page, but its unfinished session is absent from Learn's shared in-progress list. This makes an interrupted activity harder to recover than a grammar or verb lesson.

**Recommendation:** use one shared next-action model for Home, Learn and course continuation. Include grammar, vocabulary, combined sessions and workshop sessions. Give the most recent unfinished activity a clear Resume action, while keeping Review and new lessons as explicit alternatives.

Evidence: [Home continuation](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/views/home.js#L123), [Learn's sessions](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/views/learnData.js#L72), [vocabulary-only lesson recommendation](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/learning/integration.js#L143).

### A failed save can appear successful

Storage failures leave unsaved changes in memory and emit a save-error event, but the application does not present that error. Backup import can then display “Backup imported” even though the persistent profile remains the old copy. This was reproduced by forcing quota failure in an isolated storage harness; it is not a claim that a particular user's data has already been lost.

**Recommendation:** require a successful durable write before showing import/reset success. Ordinary progress saving needs a persistent, actionable warning if writing fails, including a way to export the current in-memory progress.

Evidence: [save result handling](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/store.js#L310), [import completion](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/store.js#L650), [success messaging](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/views/profile.js#L263).

### Workshop drafts and progression need consistent behavior

Free-entry workshop text is changed in memory without a save. Reloading a partially typed nationality answer restored an empty input. Cleanup also marks the view disposed before trying to save. Normal verb/word answer drafts have better persistence.

The workshop path labels later stages locked, but opening a later lesson through its direct URL works and can earn completion credit. This is a progression inconsistency, not a security vulnerability. The main course deliberately allows free browsing; that remains a reasonable policy.

**Recommendation:** save typed drafts and accents with a short debounce, flush before disposal, and choose one workshop access policy. Prefer a suggested order with prerequisite refresh options for experienced learners, unless actual locks serve a clear teaching purpose.

Evidence: [workshop input and cleanup](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/views/labFrasiLesson.js#L439), [route eligibility](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/views/labFrasiLesson.js#L66).

### Optional assistant memory is not released when leaving

The assistant's own documentation budgets approximately a gigabyte of memory and provides a release function. No application exit path calls that function. Once enabled, the engine can stay resident while the learner navigates elsewhere. A phone crash was not observed or tested.

**Recommendation:** release it on leaving the workshop and on profile changes, reuse downloaded assets when it is enabled again, and validate the lifecycle on the intended phone. Keep these experiments optional and preserve deterministic teaching when they are disabled or fail.

Evidence: [assistant lifecycle](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/learning/assistant.js#L146), [workshop cleanup](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/views/labFrasiLesson.js#L451).

## Lesson quality and the zero to C2 goal

### Preserve the improved beginner structure

The current course prepares vocabulary, teaches a small pattern, gives guided practice and moves to independent checks. Polite *Lei* is introduced through useful chunks before its forms are unpacked. Examples such as A1 *io sono / tu sei / è* and A2 completed-event versus background descriptions show a sensible teaching sequence. These are substantial improvements over testing unexplained vocabulary immediately.

The remaining problem is sometimes the repair, rather than the initial teaching. A missed farewell on *Arrivederci* can trigger a repair about greetings such as *ciao* and *buongiorno*. A missed *un'amica* can trigger examples of *un libro* and *una casa* without explaining elision. A missed *Non lo* can trigger a repair about *l'* before a vowel instead of negation placement.

**Recommendation:** author repairs for the precise facet or reviewed mistake type, with one clear contrast and a fresh retry. Mechanical recovery tests should be supplemented by checks that the repair actually explains the missed distinction.

### Make pronunciation tasks test hearing as well as spelling

Lessons explain hard/soft consonants, double consonants and intonation, but many scored checks still show printed words or ask for a written meaning. Those tasks are useful spelling practice; they do not independently establish auditory discrimination or pronunciation.

**Recommendation:** add audio-only identification with known vocabulary, then optional recording and self-comparison. Keep production assessment honest: listening to a model or submitting a recording is practice unless the response is actually assessed.

### Expand the advanced course beyond its present outline

| Stage | Units | Lessons | Authored time estimate |
| --- | ---: | ---: | ---: |
| Foundations | 3 | 8 | 57 minutes |
| A1 | 14 | 60 | 438 minutes |
| A2 | 15 | 58 | 411 minutes |
| B1 | 13 | 41 | 287 minutes |
| B2 | 13 | 41 | 287 minutes |
| C1 | 12 | 24 | 228 minutes |
| C2 | 12 | 24 | 227 minutes |

The authored estimates total 32 hours 15 minutes. This is a content inventory, not a measured learning duration or a CEFR hours requirement; optional vocabulary, verb practice, repeats and outside use add time.

C1 and C2 each contain only 12 distinct principal reading passages across their 24 lessons; paired lessons usually reuse a dossier. Median passage lengths are about 86 and 98 words. Reusing a source can teach two useful distinctions, but the learner also needs fresh, longer transfer material.

The course bundles about 25.6 minutes of passage audio overall: approximately 7.2 minutes in C1 and 7.6 in C2. Of 130 clips, 128 are synthetic practice recordings and two are public-domain literary narrations. The manifest contains no recorded natural conversation or interview. C2 has one explicit speaking portfolio, no interaction portfolios and no partner prompts.

For the intended C2 goal, the gap is communicative breadth and evidence. The [Council of Europe's CEFR Companion Volume](https://rm.coe.int/cefr-companion-volume-with-new-descriptors-2020/16809ea0d4) covers broad comprehension, flexible interaction and sustained expression; a sequence of grammar checks alone cannot assess those abilities.

**Recommendation:** retain the short teaching cards, but build larger strands of listening, reading, writing, interaction, vocabulary/register and mediation. Add licensed natural conversations and varied source material, progressively longer tasks, unseen transfer checks, revision with rubrics, and optional partner/tutor briefs. A large dictionary is an asset, but it does not replace a sequenced lexical curriculum.

### Separate path completion from performance evidence

The UI already states that open responses are not automatically graded. That honesty should remain. The C2 final dossier can nevertheless complete after eight bounded question answers while both mediation responses are skipped. This records traversal of the lesson, rather than performance of its integrated task.

**Recommendation:** keep the ability to continue without submitting private writing or speech. Show course progress separately from submitted work, self-review and external assessment. Add appropriate stage-exit tasks for Foundations, A1 and A2, and strengthen later capstones with fresh reading/listening material and optional reviewed production. Avoid presenting any count of completed lessons as proof of CEFR proficiency.

### Connect grammar to vocabulary and reference consistently

A2 has related dictionary links in only 7 of 58 lessons; its regular completed-past and -are future lessons lack those links. The newer course has no topic-specific grammar reference links in the lesson menu, although the older player does. Advanced vocabulary boards are sparse: none in C1 and boards in only 6 of 24 C2 lessons, partly because their gloss sets contain phrases or too few eligible words.

**Recommendation:** map each unit's essential words, phrases, verb cases and reference topics. Teach and retrieve that vocabulary, reuse it in later situations, and offer deeper lessons at the appropriate point. Give phrases a suitable activity instead of forcing them into single-word dictionary matching. Introduce useful words through the course as well as through their separate deck.

## Verb and word lessons

All 1,185 dictionary verbs build the five core chapters. Progressive policy covers every verb: 766 dynamic, 263 dependent on the chosen meaning, and 156 simple-only. The simple-only group appropriately avoids forcing *stare + gerundio*. Present/progressive/mixed review sequencing and separate case completion are useful foundations to preserve.

Coverage is broader than bespoke editorial depth. Twenty-five verbs have hand-authored scene frames; other lessons use sense-specific templates, validated dictionary examples or form teaching. Some chapters lack generic context targets: 95 completed-past, 70 future and 76 conditional chapters in this snapshot. That is a content-coverage gap, not proof that their generated forms are incorrect.

Current clean pacing fixtures used 23 question prompts for *avere* present and 42 for *viaggiare* present. They include different exercise types and deliberately separated independent checks, but the contrast explains why some cases can still feel very long. These are test-path counts, not a claim that every user sees the same length.

**Recommendation:** keep a brief teach-and-practice visit, then offer an explicit continuation into consolidation. Show meaningful section milestones and an expected effort range. Let later sessions provide spaced reinforcement, while retaining the internal evidence required for mastery. Editorial coverage should track distinct situations and accepted alternatives, especially for less common verbs, rather than merely counting generated questions.

Short word lessons appropriately use six answer screens and supported formats. Course boards mark a word complete only after all its relevant pairs are correct in that session without a mismatch for that word. These forms of completion are useful introductions; they are not independent recall. Manual completion is also correctly recorded as manual knowledge rather than invented answers, and completed verb cases enroll for review separately.

A small messaging defect remains: a supported-only word error can keep a “recent difficulty” label after several later supported successes because the internal unresolved-error rule requires unaided evidence that the short word lesson never provides. **Recommendation:** separate the recognition-repair message from independent mastery, without making short word lessons longer or adding unwanted typing.

## Proposed organization

Preserve the five primary tabs and the visual language. Simplify what each surface promises:

| Surface | Proposed primary purpose |
| --- | --- |
| Home | Resume the actual current activity, show today's achievable plan and offer due Review. Daily discoveries remain secondary. |
| Learn | The guided course path and its next meaningful step. Vocabulary, workshop practice and review attach to that path; browsing remains available. |
| My Course | A compact stage/unit map with Start, Resume and Revisit. Put long introductory guidance and skill explanations behind expandable help. |
| Words | Dictionary, forms, lists, useful words and deeper word/verb lessons. Show course connections where relevant. |
| Play | Varied practice of the chosen learned content, with consistent feedback and evidence recording. |
| Me | Goals, progress by skill, settings, profiles and clearly described backup/sync. |

Panoramica and Sezioni can remain alternative presentations, but should use the same recommendations and resumption model. A learner should not have to understand two competing course systems. Distinguish course stage from vocabulary/game study scope; they can remain independently adjustable, with clear labels.

The Sezioni “Full lesson / Section” control currently promises a length difference it does not provide: Full opens the next grammar lesson directly; Section creates a one-item grammar session containing that same entire lesson. This was confirmed in the browser. Remove or rename that choice until a genuine shorter section exists. Evidence: [control labels](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/views/learnSections.js#L102), [session construction](https://github.com/cmagripp/italianapp/blob/bd60180cc4eea7d9c0bd45e41584048ec752fba1/js/views/courseSession.js#L22).

Use a shared completion contract behind these surfaces. Keep lesson finished, manually known, supported recognition, independent recall and later retention separate internally. Show only the distinctions useful to the learner, such as a completed case check and a clear Review action; do not expose evidence-count jargon.

## Reliability and maintainability improvements

- **Deletion during sync:** stale merged backups/cloud data can restore deleted lists or removed list items. Add deletion records for lists and memberships, as already used for custom entries.
- **Cloud learner identity:** one cloud account has one profile row. Signing two distinct local learners into that account merges their data. Bind a remote learner identity or enforce and explain one account per learner. This was established from the code, without accessing a real account.
- **Workshop XP merge:** two devices completing different workshop lessons retain both completions after merge but retain only one 15-XP award. Give each award a stable mergeable identity and derive daily counts from those records.
- **Offline assistant:** cached model weights alone do not guarantee an offline restart when its third-party runtime is absent from the browser's HTTP cache. Serve and cache a pinned runtime from the app origin, then test a genuinely offline reopen.
- **Startup:** the app waits for the dictionary and all seven current plus six legacy course packs before first render. Load a compact index and the active stage first, while giving learners explicit offline readiness for additional stages. Benchmark on a phone before setting performance targets.
- **Long histories:** learning events grow indefinitely, and saves/sync serialize the whole profile. Benchmark realistic long-lived profiles and define a retention/compaction strategy that preserves evidence and merge correctness.
- **Backup clarity:** JSON profile backups exclude microphone recordings stored separately. State that limitation at export/import; retain separate recording export.
- **Accessibility:** remove the restrictive maximum zoom setting and verify larger text, keyboard focus, VoiceOver and contrast on actual devices. The geometry suite is not a full accessibility certification.
- **Shared UI and tests:** reuse lesson shells, feedback, dropdowns, sentence inspectors, progress and save behavior across course, vocabulary and workshop players. Preserve older saved sessions with adapters rather than deleting compatibility code abruptly.
- **Documentation:** the README and release workflow are substantially improved. Update the design specification where it still describes the older walkthrough and disappearing matching cards. Improve layout tests to account for clipping and to scroll the active internal container.

## Recommended execution order

1. **Restore trust in progress.** Fix review objective identity, missing game lapses, durable save messaging and workshop drafts. Add regressions reproducing each actual failure. Address assistant disposal before encouraging mobile use of that optional feature.
2. **Unify continuation and meaning.** Share Home/Learn recommendations and saved-session recovery; align course stage/scope labels, completion meanings and review enrollment. Resolve the misleading Full/Section choice and workshop access policy.
3. **Improve teaching where learners currently get stuck.** Add facet-specific repairs, audio discrimination, complete A2 related/reference links, concise progress milestones and better context coverage for verb lessons. Preserve short word practice.
4. **Expand the course by skills and transfer.** Define concrete outcomes and fresh exit tasks at every stage, then add lexical/phrase practice, natural audio, longer reading and optional reviewed production/interaction. Treat C1/C2 as the largest content-development project, not a small extension of the grammar question bank.
5. **Validate with representative learners and real phones.** Observe true beginners, returning intermediate learners and advanced users. Measure time, confusion, retention and transfer; test installed iPhone viewport, audio, keyboard, offline behavior and memory. Only then adjust thresholds and claims about readiness.

The highest-value first release is a reliable and coherent learning loop. The longer-term opportunity is to make the course coordinate the app's existing strengths into a sustained language-learning experience.
