# Learning functionality and integration audit — snapshot bd60180cc4eea7d9c0bd45e41584048ec752fba1

Read-only audit, 2026-10-03. Scope: verb and word journeys, learning evidence and review, course vocabulary boards, games, useful-word deck, and the sentence workshop. Repository unchanged. Home and Learn navigation, layout, pedagogy, storage and deployment are covered in the accompanying reports.

## Confirmed defects and contradictions

### P1 — a game-created due objective cannot be resolved by its Review link

The shared drill annotator records legacy IDs such as `w:sempre|adv::word::recall` and `v:andare::presente::conjugation` (js/learning/questions.js:423-440); runDrill records those IDs as adaptive attempts (js/games/engine.js:242-260). The Review selector accepts them after word or case completion (js/learning/integration.js:58-91), and its link passes the ID to the journey player (integration.js:133-139; js/views/review.js:86-93). The player focuses a review only if that ID appears in the current lesson targets (js/views/learnJourney.js:106-119), which instead have `::lesson::` IDs. For short words, the upgrade also discards incompatible focus (js/learning/journey.js:364-373).

Reproduced in a fresh isolated Chromium profile: marked `sempre` learned, played Typing, answered it incorrectly. The resulting event had `objectiveId = w:sempre|adv::word::recall`, source game, production mode, incorrect outcome. Moved only its timestamp 20 minutes back in this throwaway profile so it was due. Review displayed “sempre · Recall · Focused practice on a recent difficulty” and linked to the journey with that old objective. Completing the entire six-answer short-word review correctly created six `::lesson::meaning::...` events; the game objective's due timestamp did not change, and the same Review row remained. A deterministic verb probe produced the same ID mismatch for `andare` present.

Recommendation: define a canonical reviewable objective identity per question and map game evidence to it only when the game prompt truly tests the same skill, or route legacy IDs to a diagnostic review that records the same ID. Preserve/migrate existing queued IDs. Test game miss → due Review → successful focused review reschedules that exact objective.

### P2 — some game lapses disappear from focused Review once any adaptive evidence exists

Matching, Flashcards, Sentence, Hangman, Crossword and Speed update the older entry-level schedule via `recordAnswer` (e.g. js/games/matching.js:67, js/games/sentence.js:94, js/games/hangman.js:81, js/games/crossword.js:221, js/games/speed.js:55; js/store.js:494-505). Review discards `store.dueIds()` for **any** entry that has an adaptive skill, even when that skill is due later (js/learning/integration.js:123-131).

Deterministic fixture: manually completed `sempre`, recorded one supported short-word recall event due at 1700028801000, then set its older item schedule due at 1700003599999 (a game lapse) with `now = 1700003600000`. `reviewItems()` returned [] despite the legacy item being due. This is independent of the stale objective-ID bug above. The old item schedule may still affect other counters, but it is invisible in focused Review.

Recommendation: reconcile entry-level game lapses into the skill queue, or show the legacy due diagnostic alongside the skill schedule with de-duplication at display time; use a tested priority rule when the two schedules disagree.

### P2 — sentence workshop locks are presentation-only

The path computes a sequential locked state (js/learning/sentence-lab.js:588-609) and renders locked lessons as nonlinks (js/views/labFrasi.js:68-82). The lesson route checks only that the ID exists, not whether the stage is open (js/views/labFrasiLesson.js:66-73), and completion awards the standard first-completion credit (js/views/labFrasiLesson.js:112-117; js/store.js:587-595). A fresh-profile direct visit to `#/lab/frasi/sl-strutture-01-lo-conosco` opened the stage-four model lesson while Strutture was visibly locked. This is a progression consistency defect, not a security issue.

Recommendation: either enforce the same eligibility when opening and completing the lesson, preserving revisits for completed lessons, or remove the lock promise and present the order as suggested practice.

### P2 — typed workshop blank draft is lost on reload

The free-entry input and accent handlers only mutate in-memory `session.state.ui.drafts` (js/views/labFrasiLesson.js:439-445). They do not call `save()`; cleanup sets `disposed = true` before calling `save()`, which then exits immediately (lines 85-86, 451-452). By contrast, journey answer input saves as it changes (js/views/learnJourney.js:1010, 1022). In an isolated browser, at the saved free-nationality blank in Chi sono, typing `tedesco` after the preceding save had flushed and reloading left the input empty.

Recommendation: debounce a save on free-entry input and accent insertion; save before disposal. Regression: resume a partially typed free entry after reload.

### P3 — supported-only word errors can retain a “recent difficulty” label forever

Word short lessons and course vocabulary boards are explicitly recognition/guided, so they cannot earn independent confirmations (js/learning/model.js:19, 101-110, 251-269). Any wrong answer marks an unresolved error, and correct supported answers cannot clear it (model.js:322-326, 385). Deterministic probe: one wrong short-word recall event followed by four correct short-word recall events on later days left `unresolvedErrors.length = 1`, `confirmations = 0`, though the review schedule advanced. Review uses the unresolved flag to show “Focused practice on a recent difficulty” (js/views/review.js:92). The skill's `ready=false` is intentional because the short lesson does not claim unaided mastery; the permanent difficulty label is the mismatch.

Recommendation: represent supported recognition repair separately from independent mastery, or clear the user-facing difficulty state after spaced clean supported checks without granting independent readiness. This also matters for workshop word drills, which normalize to guided evidence (js/views/labFrasiLesson.js:400-414).

## Verified behavior and strengths

- **Verb content coverage.** All 1,185 dictionary verbs build a lesson with the five core chapters (js/learning/lesson-content.js:9-16, 286-351). The reviewed progressive data has one sense-specific record per verb: 766 dynamic, 263 sense-dependent, 156 simple (js/learning/progressive-content.js:17-26; js/learning/verb-progressive-data.js). 1,029 present chapters actually have a progressive target; the 156 simple-only cases appropriately avoid imposing it. Twenty-five verbs have bespoke reviewed scene frames in lesson-content.js:76-105; others use sense-specific templates, validated dictionary examples, or form teaching. Eighteen past cases and two future/conditional cases have no available required targets and are correctly exempt rather than impossible to complete (journey.js:727-760). This is broad generator coverage, not 1,185 individually edited lessons. Not every lesson has contextual checks: 95 past, 70 future and 76 conditional chapters had no available generic context target in the snapshot. Do not market universal scene variety across all verbs until reviewed examples grow.
- **Case completion and manual knowledge.** A verb is learned when every nonexempt core case is ready; cases remain separate, and manual marks record `source:manual` rather than fictitious correct answers (js/learning/journey.js:727-760; js/store.js:391-404). Manually known cases get a diagnostic due later, rather than fabricated mastery (js/learning/integration.js:93-115). Review only enrolls completed individual cases and respects optional expansion settings (integration.js:52-91). Explicit uncheck fences off older evidence, and completion cannot be resurrected by a stale lesson screen (journey.js:85-106; store.js:461-468).
- **Adaptive pacing and correction.** A completed verb target needs independent production, different variants, spacing, and repaired errors; guided cards, matching, letter-bank support and answer audio do not masquerade as unaided mastery (js/learning/model.js:251-269, 296-368; js/learning/journey.js:142-166). The v2 flow stages forms, progressive construction where appropriate, and mixed review; failed checks stay in repair (journey.js:197-215). Clean traversal in existing tests ranged from 15 questions for `piovere` present to 23 for `avere` and 42 for `viaggiare`. This is rigorous but can feel long; expose an expected range and an honest pause/quick-introduction choice rather than silently loosening readiness.
- **Interaction quality.** Verb lessons vary multiple choice, letter construction, guided matching and independent typing; matching pairs have per-row diagnosis and can be repaired, while answer/form/example audio is accessible (js/learning/journey.js:142-166, 516-554; js/views/learnJourney.js:382-393, 703-727, 969-1005). Input drafts save on each change; saved question snapshots allow backward review without regrading (learnJourney.js:466-518, 1010-1022).
- **Short word lesson and course vocabulary.** The ordinary word path has two teaching sections and six answer screens, using article/plural checks or a mixed matching board when applicable (js/learning/lesson-content.js:481-512). It intentionally grants supported completion, not independent mastery (js/learning/journey.js:695-710). Course lessons synthesize meaning, reverse-recall and forms boards for resolvable dictionary words; 86 lessons produced boards, 320 board steps and 1,098 pairs in the deterministic suite (js/learning/course-words.js:188-205, 213-325). A course board marks a dictionary word learned only if all available meaning/recall/article/plural targets match within one session **and no mismatch on that word occurs in that session**; a short-word lesson requires all its own slots in one session (journey.js:763-798). The boards do not incorrectly grant independent mastery. Six nouns were excluded by the board-packing rules in the test; the exclusion is explicit and preferable to crediting impossible article pairs. Gloss resolution is weaker in advanced lessons (C1 43.8%, C2 53.1%), mostly because phrases and dictionary coverage diverge; consider a parallel phrase practice track instead of forcing false dictionary matches.
- **Useful words.** The hand-curated Parole utili deck has 78 resolvable, unique entries in six groups: questions 10, connectors 18, indefinites 13, pronouns 11, time/place 18, quantity 8 (data/useful-words.json; js/useful-words.js:1-61). Each row opens the standard word journey, and set/group Play routes to Matching (js/views/browse.js:160-195). This is cohesive for discovery, though the Matching game's results still follow the older item SRS as described above.
- **Sentence workshop.** The four-stage path contains 21 lessons and 168 authored activities, including build, cloze, conversations and own-sentence composition. It saves completed lesson timestamps and learner sentences, and its own page resumes an open session (js/views/labFrasi.js:68-95; js/views/labFrasiLesson.js:66-86, 112-129, 246; js/store.js:582-605). Its free-entry word drill records guided journey events on the word's canonical objective when available (labFrasiLesson.js:400-414). However, workshop progress is separate from course grammar readiness, and Home/Learn do not surface its in-progress session; those are navigation/integration opportunities, not proof of lost session state.

## Cohesive product recommendations

1. Use one objective registry for lesson, game, course-board and workshop evidence. Each event should declare the exact skill tested, evidence strength, and canonical review destination. The two Review defects above arise from separate identity and schedule systems.
2. Make the learner's “learned” state visibly distinct from “can recall unaided” and “remembered later.” Short words and matching boards are a valid introduction, but the current learned check and review messages blur supported completion with retrieval confidence (journey.js:695-710, 763-798; model.js:366-388).
3. Give workshop practice an explicit relationship to course lessons, perhaps through lesson grammarRefs and a related-practice surface. Keep open responses as practice/self-review unless actually assessed; do not auto-award grammar readiness from them.
4. Offer direct access to relevant workshop stages for already learned grammar/verb cases, or frame its strict sequence clearly. Route locks and progress checks must agree.
5. Track editorial coverage separately from generated morphology: reviewed lexical frames, soundness of English prompts, accepted alternatives, and advanced phrase coverage need ongoing editorial QA even when every deterministic traversal passes.
