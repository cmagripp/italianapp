# Learning and persistence contracts for Phases 0–2

Prepared 3 October 2026 against `bd60180cc4eea7d9c0bd45e41584048ec752fba1`. These decisions implement the preservation rules in the [comprehensive plan](../../PLAN-UNIFIED-LEARNING-OFFLINE-AI-2026-10-03.md) and [roadmap](../../IMPLEMENTATION-ROADMAP-2026-10-03.md). They need integration review; an authored contract is not evidence that its implementation or phone validation has passed.

The existing profile schema is version 2 and the adaptive domain is version 5. The representative profiles in `tests/fixtures/phase-0-2/` are synthetic. None were taken from a learner's account. Additive profile fields do not imply a new learning schema; any changed interpretation of stored events, components or compaction records requires an explicit learning-version decision and an older-client compatibility test.

## 1. Phase boundaries and preserved behavior

Phases 0–2 establish contracts and repair the existing application. The conversation, sense-aware catalogue, unified daily plan/review experience, new shared player and production AI/speech services below are interface designs for later phases. Defining them does not authorize implementing those later features.

- Preserve historical checks, explicit individual manual choices, XP, custom words, lists, evidence and exact compatible unfinished sessions. Do not fabricate successful answers from a checkmark, a timestamp, a list, a transcript, a counter or old aggregate statistics.
- A whole verb requires all available core cases: `present` / `presente`, `past` / `passatoProssimo`, `background` / `imperfetto`, `future` / `futuro`, and `condizionale` / `condizionale`. A true unsupported case remains explicitly exempt; an optional expansion is not a sixth mandatory core case.
- A short word lesson remains principally non-writing. Supported completion is valid completion; it neither requires nor implies independent written production.
- Strict accents affects subsequent typed submissions. It must not retroactively regrade old events, inflate original evidence, or turn an explicit wrong answer choice into a correct one.
- Optional cloud sync and replaceable downloaded packs remain separate from local learner data. Installed offline content survives a failed migration, reset or pack update unless its explicit removal was requested.

## 2. Completion, evidence, assistance and review

`learning.completions[completionKey(entryId, caseId)]` is enrollment/choice, independently of `learning.events[eventId]`. Retain the existing record shape `{entryId, caseId, id, checked, at, source, flowVersion?}` and `*` legacy whole-entry record. A manual case record overrides a legacy wildcard for that case. A false record is a deletion fence, not absence. Ordering is deterministic by timestamp and stable payload/ID; a later offline merge cannot silently drop a fence.

Manual marking awards no XP, correct-answer counts, independent-ready state or remembered state. It enrolls a gentle diagnostic for the checked cases. Manual unchecking preserves existing answer history and old XP while suppressing completion and normal review for the unchecked case. Only genuinely fresh compatible evidence after that fence can restore automatic completion; a stale completion screen cannot. A case-specific uncheck must not uncheck its other cases.

An event has stable `id`, `epochId`, installation `deviceId`, `sequence`, `sessionId`, `index`, submission `at`, exact `objectiveId`, `entryId`, skill, mode, outcome, assistance and content policy/version. Deduplicate by immutable event identity before awards or daily statistics. A caller's source or explanation is not evidence of assessment. Record the actual assistance (`hint`, `matching`, answer audio, letter bank, correction/repeat, model supplied text) before committing the answer. Typed construction which fills an article, conjugates a verb or resolves agreement is assisted even when the learner supplied the lemma.

Keep recognition, assisted construction, unaided production, listening and delayed retrieval distinct. A successful permitted accent restoration supports the non-accent target, but accent spelling is unassessed. Because current v5 components require Boolean `ok`, omit unassessed orthography components rather than encoding `ok:true` or `ok:false`. A future nullable component needs a versioned migration.

**Identity/alias design:** an objective registry entry declares `{id, entryId, senseId?, caseId?, skill, evidenceModes, policyVersion, contentVersion, reviewDestination}`. Aliases declare `{legacyId, canonicalId, relation:'equivalent'|'diagnostic', rationale, mappingVersion}`. An equivalent alias is permitted only for the same sense, case, skill and evidence semantics. Old `entry::tense::conjugation` cannot be assigned indiscriminately to one person/context target; broad legacy recall cannot become specific written-production proof. A diagnostic alias keeps the old difficulty and records diagnostic review against its original identity. Preserve unmapped evidence with a visible compatible fallback; do not discard or claim it was tested by a different exercise.

**Review eligibility:** a completed word, completed verb case or independently eligible grammar target can be reviewed. An unfinished verb case stays out of ordinary review. A legacy item lapse must remain actionable even if an adaptive target for the same entry is due later. A reviewed answer must update the exact underlying due difficulty. Successful delayed recognition can repair a recognition difficulty and lengthen its recognition schedule without granting written-production readiness. Scope filtering may restrict new practice; it does not erase due records. Grouping into new unified review rows/sessions belongs to Phase 3.

## 3. Prospective awards and historical XP

Keep the historical reward values for the repair release: word completion 10 XP; whole available-core verb completion 30 XP; workshop lesson completion 15 XP; correct unassisted adaptive attempt 2 XP; correct assisted adaptive attempt 1 XP; incorrect/revealed/skipped/ungraded 0 XP. Current game reward rules remain unchanged until explicitly rebalanced. Manual checks/unchecks and open-chat/model praise yield 0 XP.

Prospective durable awards use a stable key derived from epoch and reward occurrence, such as `epoch|attempt|eventId`, `epoch|completion|entryId`, or `epoch|lab|labKey|lessonId`. The workshop completion award is stable across devices, even when timestamps differ. Record `{id, epochId, kind, sourceId, xp, at, dayKey, policyVersion}`; accept an already recorded ID once. Source validation precedes awarding. Completing the same lesson on two devices gets one completion award; completing two different lessons gets two. Returning to an old completed screen, importing the same backup twice, manual toggling and conflict retries cannot farm rewards.

Historical XP remains an explicit baseline; only rewards actually represented in existing evidence can be subtracted from that baseline when introducing an award ledger. Do not infer historical workshop awards from `lab.done` and then add them again. Aggregate legacy XP cannot be reconstructed into fictional events or reliable per-day sources. Merge that baseline conservatively (the existing maximum for snapshots of the same learner), and merge prospective awards by ID. Preserve historic day counters and label any unknown provenance internally; new award day totals derive from their recorded `dayKey`, not the importing device's timezone. Reset establishes a new reward epoch; stale old awards cannot restore reset XP. Existing five-case/manual-first-completion protections continue to apply.

## 4. Durable saves, imports, reset and recovery

An explicit `saveNow()` must settle only after the corresponding durable commit. It returns a success result or rejects; failure cannot resolve as success. Ordinary debounced/unload saves catch rejection and emit a persistent `saveError` state with the unsaved latest data still exportable. Queue failure must not poison subsequent retries. A clean caller awaiting an in-flight queue sees that commit's failure. A later successful save clears the warning. Profile switching cannot report a successful switch after the initiating learner's unsaved changes were dropped.

The localStorage fallback is synchronous primary storage; do not require a second full-size mirror for every normal edit. IndexedDB uses the existing unload mirror with unique write identities, preserving a newer mirror until its own commit. Quota, blocked database, transaction abort and malformed recovery copy receive distinguishable failure/recovery results where possible. Never delete the only recoverable copy to make room for the candidate.

**Migration/import protocol (same for future schema migrations):**

1. Capture the initiating local profile/learner identity and write revision. Validate the input shape and supported versions without mutating the active profile. Reject future schema versions without changing active state.
2. Flush current edits or retain them as the recoverable snapshot. Persist a pre-operation snapshot containing the complete old schema, profile identity, capture time, operation ID and integrity digest, or obtain a successful explicit export. Verify that snapshot can be read and parsed by the old-schema restore path. If durable preservation fails, leave prior state active and report failure.
3. Transform a clone deterministically. Normalization is idempotent; running it twice changes neither history nor rewards. Validate item/list/custom references, epoch, duplicate event/award IDs, completion fences and exact compatible sessions. Unknown legacy identifiers remain recoverable.
4. Write the candidate durably and verify it before activation. If verification fails, restore the old primary from the snapshot; do not show imported/reset/migrated success. Preserve the old snapshot until the candidate is known good and expose recovery/export if rollback itself fails.
5. Activate exactly the verified candidate only if the captured profile and revision are still current. Publish profile/change/success after durable activation. On concurrency, rebase or reject safely; never apply it to the newly selected learner.

Restore reads the saved source schema directly before applying any new migration. Restoring a pre-reset snapshot is an explicit replace/recovery action; automatic merge must still honor newer reset epochs. A failed reset does not delete recordings first. Delete/reset-associated recordings only after durable profile transition, retaining enough state to recover if an audio deletion fails. Model/course assets are outside the reset boundary.

**Safe export procedure:** before a migration, export JSON and verify a fresh isolated import reproduces its progress, lists/custom records, XP and exact compatible drafts. Profile JSON currently excludes course microphone blobs and installation/cloud tokens. Explicitly state that scope in the backup UI and separately export wanted recordings. The synthetic recording sidecar is inventory only; it contains no claim that profile JSON already backs up audio.

## 5. Lists, deletions and profile/cloud identity

List and membership mutation records need timestamps/IDs and tombstones, just as custom-word deletion already has a tombstone. Proposed additive fields are `listsDeleted[listId]` and `listItemDeleted[listId][entryId]`, or an equivalent versioned membership operation map. A delete/remove beats a stale backup's earlier creation/addition. A deliberate newer re-add of the same membership can win; a deleted list is recreated with a fresh list ID. The builtin `bank` cannot be deleted. Renames and independent additions remain mergeable; cleanup removes deleted IDs from scope without deleting retained evidence/reward identities.

Local profile ID identifies an installation slot, not a portable person. A stable `learnerId` is preserved on export and across the same learner's devices. Creating another local learner generates another identity. Replacing from backup is an explicit restore which can restore that identity; automatic/merge import must check identities before any state mutation. A mismatched cloud learner cannot merge merely because both profiles authenticate with the same account. Matching names/avatars are insufficient. A legacy remote profile with no identity requires a deliberate claim/adoption flow bound to the active profile; do not silently bind every old local profile to one remote row. Credentials stay outside exported profiles.

Cloud operations capture profile ID, learner identity and account ID before request. Check all three after every await and before merge, push or saving credentials. Keep existing atomic server revisions and bounded retry. Evidence/preferences/awards may sync; device-local player/workshop drafts and future conversations/audio stay local by default. Optional future conversation sync requires its own explicit setting. Tokens for one local slot must never attach to another after a late sign-in/signup response.

## 6. Fast evidence and compaction

Append and index evidence without normalizing, sorting and replaying every lifetime event on every answer. The index must include objective, session position/chronology, epoch and content policy/version, because spacing and readiness intervals depend on those relations. Invalid/duplicate events cannot move schedule or XP. Return isolated summary objects so view decoration does not mutate cached state. Out-of-order events and imported merges invalidate/rebuild affected indexes safely; tests compare their results against complete deterministic replay.

Compaction is a distinct durable transformation, not deletion of old events after caching summaries. Until a merge-safe implementation passes its fixtures, retain the event log. A future checkpoint stores schema/policy version, epoch, canonical objective mapping version, through-position/device coverage, sufficient reducer state, tombstone/manual-fence coverage, reward deduplication identities and an integrity digest. It must represent chronology/spacing, unresolved errors, readiness intervals, per-session scheduling and delayed recognition without fabricating proof.

Never merge checkpoints by summing their totals. Overlapping histories, an old backup and an offline device require set-like deduplication with retained IDs/ranges or acknowledged coverage. Reset epochs supersede every older checkpoint/event/award. Compaction cannot erase an uncheck fence or deletion tombstone until every accepted replica/backup policy prevents resurrection. A failed compact/save leaves the previous log active and recoverable. Measure 1k/10k/50k attempt profiles; desktop timings are reported as desktop measurements, and phone latency remains separately unverified.

## 7. Submission comparison and display provenance

A shared answer comparison receives original text, reviewed accepted alternatives, task typography rules and the profile's setting at submit time. Its serialized result carries:

```text
policyVersion, inputMode (typed | choice | speech-transcript)
originalText, normalizedText
matchedAnswerId, matchedAnswerText
matchKind (exact | accent-only | invalid | ambiguous | ungraded)
accentDifferences [{start, end, before, after, kind}]
displayText, outcome, accentStrict, assistance
```

Use NFC first. Case, permitted surrounding/trailing punctuation, whitespace and apostrophe typography are explicit task rules. Apostrophe insertion/removal and missing letters are never accent-only. Fold Italian vowel accent differences only; do not strip every combining mark from names and other languages. Prefer an exact valid alternative over a folded match. If several non-equivalent accepted alternatives fold together, preserve ambiguity unless the prompt independently resolves it.

With accents permissive, a unique reviewed accent-only match is correct for its non-accent target. On submission, change only verified vowel accent marks in the actual submitted text; retain casing, punctuation, synonym choice, article, agreement and word order. `Un CAFFE, per favore!` becomes `Un CAFFÈ, per favore!`; `cafe` cannot become `caffè`. With strict accents, preserve the original field value and show specific spelling feedback; reveal the correct model separately. Explicit choices `e` versus `è` always remain distinct. Unknown free text/names are never mechanically rewritten.

Save original, display, accepted alternative and setting with the result atomically; reopening feedback uses that result, not the new profile setting. A restored spelling is not a second response, a second award, or unaided spelling evidence. Speech-supplied accents are transcription provenance and never typed spelling evidence; typed transcript edits remain distinguishable.

## 8. Sense and language versions — design only

Separate stable `entryId` from stable `senseId` and construction ID. Language records declare `{schemaVersion, contentVersion, senseId, entryId, partOfSpeech, glosses, forms, constructions, level, provenance, reviewedAt}`. Sense IDs are editorial identifiers, not hashes of English wording. Auxiliary, progressive suitability, accepted participles and agreement belong to the sense/construction where usage differs. Course prerequisites refer to taught senses/forms/constructions with versioned mapping.

Legacy mappings declare one-to-one equivalence, rename, many-to-one merge, ambiguous split or retired diagnostic destination. A legacy `w:pesca|noun` completion can be preserved as an unresolved old completion; it must not prove both fishing and peach senses. Keep legacy progress and display a compatible old/diagnostic destination until an explicit choice/assessment determines the new sense. Ordinary copy/format fixes preserve applicable evidence; changed tested meaning/answers use a new compatible content policy. Incompatible drafts retain their snapshot for recovery and receive an honest restart/migration choice; they are not silently discarded.

## 9. Conversations, summaries and audio — design only

All future records are keyed by learner/profile and stable `threadId`; participants have stable IDs independent of names, roles and agreement preferences. Keep three durable stores/records:

- **Draft:** `{threadId, turnId, revision, mode, typedText, recognizedText?, transcriptEdits?, temporaryAudioRef?, selectedHelp, policySnapshot, updatedAt}`. Changes of support/input mode preserve the draft. Cancel does not commit a turn. Generation/capture/recognition results verify learner/thread/turn/revision before use; stale work is discarded.
- **Committed turn:** `{threadId, turnId, revision, participantId, role, originalText, displayText, inputProvenance, acceptedEdits, correctionRefs, at, policySnapshot, modelVersion?}`. Commit is durable and idempotent before it appears as sent. Speech recognizes a hypothesis, learner confirmation/edit stays distinct, and language corrections do not overwrite original meaning. Free text/exposure/praise earns no correctness reward or automatic completion.
- **Summary:** `{threadId, revision, throughTurnRevision, sourceRefs, items, invalidatedRefs, generatedAt, policyVersion}`. Each vocabulary/construction/correction/note links to specific turn revisions and its sense/source. An edited/deleted source invalidates affected notes; summary regeneration never creates graded evidence. Summary indexes can be rebuilt; committed original turns cannot be replaced by a lossy summary.

Keep captures ephemeral by default. Retain original audio only on explicit Save recording and record `{audioId, learnerId, threadId, turnId, consentAt, mimeType, bytes, duration, createdAt}` plus separate binary storage. Transcript import does not assume audio exists; export optionally includes chosen recordings with verified references. Profile deletion/reset handles its own recording prefix, never another learner's. AI-pack removal does not delete transcripts or chosen recordings. Runtime captures microphone only in the foreground, pauses/releases on navigation, profile change, lock or interruption, and requires explicit Resume before restarting. No spoken mode or production storage is implemented by this contract.

## 10. Verification ownership

`tools/test-phase-migration-fixtures.mjs` verifies additive legacy migration, idempotent round trips, explicit check/uncheck fences, reset versus stale merge, session/profile boundaries, future-schema rejection and recording backup scope. The manifest records observed baseline regressions separately from preservation assertions. Passing this suite alone does not prove durable staging, cloud identity adoption, UI accent display, compaction or physical-phone behavior. Those require the implementation tests/browser/device gates owned by their repair package. Track implemented, independently reviewed, device validated and live verified as separate statuses in the root ledger.
