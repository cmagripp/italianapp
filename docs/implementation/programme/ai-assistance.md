# Shared validated practice assistance

The workshop, current course and retained Grammar player now have an exercise-scoped consumer of an installed local service. Production still has no approved conversation provider, so these optional controls remain hidden. Authored hints, dictionary entry and normal practice continue without a provider. No model is downloaded or acquired by opening a lesson, and no canned model reply is substituted.

`ai-assistance.js` captures profile, learner, epoch, session, exact canonical question/activity and current input. A SHA-256 source revision and an installed-provider revision bind each request. Editing the intention cancels scoped work; a changed source, owner, epoch, provider or closed sheet cannot publish a late response or apply wording. Draft persistence must succeed before generation. A suggestion requires validated-service language-policy provenance; generated conversation prose is not accepted as a free grammar explanation. Explanation cards copy the service's verified source material. A hint containing an exact normalized canonical answer is rejected. This is a limited disclosure guard, not proof that a model cannot reveal an answer indirectly or make an incoherent hint.

`practice-help.js` persists original intention drafts and viewed receipts in the ordinary saved lesson session. Reopening restores only a matching original draft, never a saved generated response as fresh authority. Explicit use inserts wording into an editable, unsent workshop or portfolio draft. The original intention remains available beside that draft and in the saved session work. The learner still submits to the normal canonical answer checker. Use is consumed once, including a double activation while saving. Audio plays only after an explicit request; restored help does not autoplay.

Viewing help creates no learning attempt, completion, learned status or recall claim. A subsequent real Course/Grammar answer carries the existing hint assistance tag. Workshop answers and any canonical new-word drills after AI wording help retain `ai-intent`; those assisted drills cannot mark a word learned. Portfolio writing remains ungraded. Original wording and its exact source receipt remain separate from the final typed submission. The legacy Grammar wrapper also now checks learner and epoch across its lazy load, input, answer, dictionary and cleanup callbacks.

Task prompts for intent/hint/explain use bounded exercise context and task-specific examples rather than conversation continuations. Those tasks cannot emit generated corrections. Existing conversation prompt text and historical negative model-trial artifacts are retained. The current teaching resolver retrieves from supplied verified grounding; a complete production rules/senses/analyzer installation and real task-quality evaluation remain required. Passing a language-range check alone does not establish meaning preservation, usefulness or grammatical truth for generated prose.

Validation: 10 assistance unit checks and 30 existing service checks pass. The browser suite covers draft persistence, source/provider leases, exact-answer disclosure rejection, canonical assessment tagging, explicit audio, read-only exposure and delayed initial host loads; final engine-specific counts are retained in `ai-assistance-chromium.json` and `ai-assistance-webkit.json`. Browser fixtures explicitly install a test-only generator and language-policy fixture. They establish no real model quality or physical iPhone readiness. Existing sentence-lab engine, current Course engine and retained Grammar durability checks also pass.

Journey is awaiting the learning agent's stable scene-revision handoff. No native/cloud product switch or production model activation is part of this slice.

Evidence: `ai-assistance-chromium.json`, `ai-assistance-webkit.json`; reproduction: `node --test tests/ai-assistance.test.mjs` and `node tests/ai-assistance-e2e.mjs` (set `COURSE_BROWSER=webkit` for WebKit and the environment's Playwright package path).
