# Native Qwen investigation and production decision

The single approved native Qwen3-8B trial proves that the provisioned local model runs on the Mac and through a real iOS-simulator C++/Swift bridge. It does **not** pass the Italian practice gate. The shipped product remains offline web, with generated conversation unavailable. Native investigation permission has not selected a new distribution platform, enabled a production provider or established physical-iPhone compatibility.

## Reproducible candidate and runtime

The official [Qwen GGUF export](https://huggingface.co/Qwen/Qwen3-8B-GGUF/tree/7c41481f57cb95916b40956ab2f0b139b296d974) is pinned to `7c41481f57cb95916b40956ab2f0b139b296d974`. `Qwen3-8B-Q4_K_M.gguf` is 5,027,783,488 bytes (4.68 GiB), SHA-256 `d98cdcbd03e17ce47681435b5150e34c1417f50b5c0019dd560e4882c5745785`, Apache-2.0. The complete license and original model card are retained under `dev/phase-1-ai-trial/native/notices/`. The card documents llama.cpp support and non-thinking sampling recommendations; multilingual support is upstream metadata, not this programme’s Italian-quality evidence.

The official [llama.cpp b11146 release](https://github.com/ggml-org/llama.cpp/releases/tag/b11146) is pinned to `7fe450e19305b828c199d602c23a8337aaa1f03b`, MIT. [Pins](../../../dev/phase-1-ai-trial/native/native-pins.json) preserve exact Mac archive, XCFramework and source archive hashes; the full MIT notice is retained. The published XCFramework contains device-iOS and macOS slices, but no iOS-simulator slice. The investigation therefore compiled the pinned official source for arm64/iOS26.5 simulator with Metal/Accelerate and a small C++ bridge. This is an investigation adapter, not a production pack installer or cancellable production engine.

Only one 5.03 GB model was downloaded. Its simulator copy is an owned hard link to the verified weight file, rather than another allocation. Verification after the trial found 20.61 GiB free, above the 5 GiB floor, and reconfirmed the complete weight and runtime archive hashes. No unrelated cache was removed. The app bundle contains frozen prompts, not the weights. Large assets and built binaries remain in ignored trial directories.

## Actual quality and measurements

The same 26 frozen cases previously used for the Phi screen were tested without tuning prompts after output. These comprise the 24 fresh held-out situations and two opening/setup cases. The teaching-separation prompt permits conversational prose, while verified cards and correction explanations are rendered independently. Context was 4,096 tokens, output ceiling 512, temperature 0.7/top-p 0.8/top-k 20/min-p 0/presence penalty 1.5/seed 42, non-thinking. These official Qwen settings differ from the earlier Phi sampling; this is a candidate screen rather than a controlled scientific model ranking. Inputs consumed 724–897 tokens and outputs 23–70, so the schema had ample output budget.

The [full Mac raw report](ai-native-qwen-mac.json) retains every prompt, request, completion, token count, timing and validation result. All 26 requests produced outputs; 23 passed deterministic metadata checks. [The independent per-case review](ai-native-qwen-review.json) records 9 useful passes, 8 partial responses and 9 failures, with explicit reasoning and no Italian educator or learner-calibration claim. Median whole-response latency was 3.31 seconds, nearest-rank p95 7.01 seconds. The maximum 500 ms sampled process RSS was 6.71 GiB on an M1 Max/32 GB Mac. Prompt cache reuse contributes to these desktop timings; they are not phone latency or working-set proof.

The deterministic guards rejected:

- Two fabricated word-definition “corrections”, whose quoted originals did not occur in learner input and whose rule IDs were unverified.
- `ho venuta → ho venuto`, where the supplied rule verifier requires `sono venuta`.

Accepted prose still included a misleading positive teaching claim about the erroneous `ho andata` construction, despite an empty correction array. It also conflated a confirmation deadline with the visit date, failed to clarify physical versus emotional closeness and inferred time savings from walking to school without evidence. Other replies were safe but unhelpful: asking again who had not accepted, or asking what to cook without using the known no-fish context. A fish question in response to “no meat” is recorded as topic drift, **not** a definite negation contradiction; Italian commonly distinguishes those food categories. Valid reflexive language, no-purchase intent, Sunday scheduling, uncertain-ASR review and formal active-speaker opening had useful responses. Separate cards cannot make misleading generated prose true.

The Mac schema allowed an arbitrary rule ID when no rules were retrieved; independent validation caught it. The simulator’s GBNF forces empty corrections in that situation and enumerates supplied rule IDs otherwise. It also uses explicit Qwen ChatML/non-thinking prefill and resets its context for each case. These decoding/cache differences are recorded rather than treating simulator output as byte-identical to the Mac benchmark. In the simulator plumber case, fabricated correction metadata disappeared, but a definition still appeared in free prose. Constrained metadata therefore remains insufficient for the teaching-separation contract.

## Simulator results and limits

The actual target was the approved **iPhone 16 Pro Max / iOS26.5 simulator**, UDID `80FC8AD8-F787-4C66-AC1B-462ABD6E2AEA`, hosted on the M1 Max/32 GB Mac with Xcode26.6 build17F113. Native Metal exposed `Apple iOS simulator GPU`, unlike the earlier browser’s missing WebGPU adapter. [The native Metal attempt](ai-native-qwen-simulator-metal.json) produced zero outputs: context initialization/warmup had not completed at the last observed 238 seconds, and the run was terminated. Sampled process RSS reached 8.74 GiB; the retained stack shows decode/Metal command-buffer waits. This is a bounded incomplete simulator run, not a reported crash or a physical-phone failure.

[The CPU-only fallback](ai-native-qwen-simulator-cpu.json) used zero GPU layers with KQV/operation offload disabled. It loaded in 9.38 seconds and returned actual local completions. The intended first-three-case/approximately-eight-minute limit was overrun while the unattended app loop advanced during agent context handover. It was stopped at the next inspection with **all 16 completed rows preserved** and the ten remaining cases explicitly skipped. This is a recorded execution-control failure, not a selectively trimmed quality result. The source that executed is retained separately. The revised investigation app now defaults to a three-case cap and 480-second between-case budget; the revised build compiles, but was not rerun to change the evidence.

Those 16 CPU responses took 18.79–103.01 seconds, median 32.22 seconds. Post-load `task_vm_info.phys_footprint` was 5.01 GiB and the highest end-of-turn sample 5.07 GiB. Process RSS samples were larger; RSS and physical footprint measure different things and cannot be substituted. `modelBytes` in the raw app report is llama.cpp tensor size (5,021,827,072 bytes), not the 5,027,783,488-byte GGUF file. [Metadata replay](ai-native-qwen-cpu-validation.json) accepted all 16; no independent language policy was applied, so this establishes integration, not semantic approval.

These measurements replace a speculative “5–6 GiB should fit” claim with observed host data. An 8 GB-class phone has other system/app/speech allocations, memory-pressure limits and thermal constraints. Neither this simulator nor a 32 GB Mac demonstrates the phone can run the pack. No further candidate was downloaded. The [Apple-native report](ai-native-apple-prototype.md) separately preserves FoundationModels’ advertised Italian availability followed by failed real inference, unavailable simulator recognition APIs, and actual tiny synthetic voice measurements. None of those simulator states determines physical-device Italian quality.

## Feasible architecture and the remaining gates

| Component | Implemented evidence | Production requirement |
|---|---|---|
| Durable conversations | Profile/thread storage, source revisions, drafts, cancellation leases and browser tests | Installed provider and actual runtime still absent; no model fallback is enabled |
| Written generation | Serialized service, bounded prompts, stale-source rejection, metadata validation and deterministic cards | Verified Italian/meaning policy and a candidate that passes broad unseen cases |
| Grounded teaching | Stable dictionary sense IDs; exact source/rule correction verification contract | Adapt reviewed sense records into grounding and author a versioned rule catalogue with independent verifiers; trial rules are not a released grammar engine |
| Help/reply support | Source-bound slot choices and separately checked completed suggestions, assistance provenance | Every suggestion needs genuine language-policy approval; an always-true test policy is not releasable |
| Manual/hands-free transport | Real PCM AudioWorklet capture, temporary replay, explicit audio-save consent, lifecycle cancellation and durable one-send/retry behavior | Installed local recognizer, calibrated uncertainty and VAD, validated Italian voice; real learner/device and endurance tests |
| Browser packs | Streamed SHA-256 verification, staged activation, pinned allowed model hosts and local executables | Actual runtime wired to verified cached shards, eviction/cold-reopen/device qualification; native single-file GGUF is outside the browser’s 512 MiB shard contract |
| Native delivery | Standalone Swift/C++ capability prototype; actual simulator CPU inference | Separate product decision, physical-device runtime/speech/memory qualification and durable web-data migration/distribution design |

`createAIService()` defaults to `requireLanguageValidation:true` and refuses to call the model without a validator. The production provider is absent. Preserve both facts. A lexicon membership check, forbidden-word regex, second unvalidated model or schema-only guard cannot honestly establish Italian grammar, meaning preservation, ambiguity handling and level bounds. The next policy work should make each accepted construction and source of authority explicit, reject unsupported teaching assertions, check learner-context entailment/contradiction and abstain on ambiguity or uncertain recognition. Restricted coverage may leave many turns retryable/unavailable; it must not manufacture scripted partner replies or pretend full dynamic conversation is implemented. The supplied-rule verifiers and protected negation/quantity/name multisets apply to correction spans, not all partner prose, so additional semantic validation is necessary.

The least disruptive **investigation** architecture is to retain the existing web learning/conversation UI and profile storage, with a scoped native runtime/speech adapter behind the existing provider API. Apple provides [reply-capable WebKit JavaScript messages](https://developer.apple.com/documentation/webkit/wkscriptmessagehandlerwithreply) and [persistent website data stores](https://developer.apple.com/documentation/webkit/wkwebsitedatastore), which are credible bridge primitives. This is an architectural inference from the APIs, not a tested Parola wrapper. A stable origin, IndexedDB ownership, service-worker/offline shell behavior, real process-termination recovery and export/import migration must be proved before relying on it. The browser’s existing origin data should remain intact; a native origin/store would need explicit scoped backup import, rather than silent data moves. A full SwiftUI/storage rewrite would duplicate considerably more already tested functionality.

The native adapter must carry request IDs, profile/thread/source revisions and provider epochs; settle cancellation through the engine; reject late work; never resend an already committed learner turn; release model memory on pressure; and stop capture before ASR/generation/playback. Native packs would use an application-controlled pinned manifest, URLSession streaming SHA-256/size checks, temporary staging, disk-floor checks and atomic verified activation, retaining model/runtime notices. No generated URL may select executable or weight downloads. Apple system models remain OS-managed capabilities rather than redistributable pinned packs. TestFlight/App Store signing and distribution, or a development-only physical-device trial, requires a separate explicit delivery choice; none occurred here.

The concrete next investigation, if later authorized, is physical-device qualification using the **already provisioned** pack and/or a functioning eligible FoundationModels device, with fresh held-out cases. Record actual available memory, foreground working set/jetsam, Metal resources, cold offline reopen, concurrent speech/model memory, interruption, heat and sustained latency. Lower context/quantized KV could be evaluated for memory using existing weights, but does not erase current quality failures. A functioning Apple system model could answer the presently unknown quality question; availability metadata alone cannot. Neither path justifies another speculative large-model download now.

Safe programme progress is therefore source/rule integration, targeted conversation study, broader educator-reviewed held-out cases and robust speech/provider plumbing while readiness stays false. Full written/manual/hands-free/coach capability still requires those gates and the eventual thirty-situations-per-level corpus; this small comparison is a filter, not completion or certification.

## Reproduction

Run `node dev/phase-1-ai-trial/native/verify-native-assets.mjs` from the worktree to stream-check the already provisioned artifacts without downloading. `bash dev/phase-1-ai-trial/native/build-native-runtime.sh` reproduces the simulator static runtime/bridge; `bash dev/phase-1-ai-trial/native/build-qwen-simulator.sh` builds the separate app without installing or launching. The current source defaults to three cases; `PAROLA_NATIVE_CASE_LIMIT` and `PAROLA_NATIVE_BUDGET_SECONDS` can explicitly override the bounded investigation only. Use `SIMCTL_CHILD_PAROLA_NATIVE_GPU_LAYERS=0` when launching the CPU fallback. Preserve the simulator `Documents/native-qwen.json` before terminating its bundle. Install weights only into the separate owned investigation container; no production file or learner storage is involved.

For the desktop frozen screen, `start-mac-server.sh` binds the verified model on localhost8162 and `mac-qwen-benchmark.mjs` executes the saved 26 cases. These scripts write raw reports, so use a new destination/copy before intentionally repeating. [Execution provenance](ai-native-qwen-execution.json) retains hashes of the exact executed inputs/source and copies of source before later cap fixes. Reproduction code and compile success support the evidence; they do not open the production gate.
