# Scoped browser speech foundation

`js/conversations/speech-session.js` supplies the manual and foreground alternating handsfree lifecycle around the actual conversation controller/repository. Importing it installs no production speech provider. The browser application still requires separately measured local recognition, voice, language and device gates. It never calls browser SpeechRecognition or substitutes a cloud recognizer. The existing language service remains fail-closed without language validation.

Create a session with `{controller, repository, threadId, isCurrent, speech, onChange}`. The installed scoped speech lease has `readiness()` returning `{recognition, voice, vad, reason}`, `recognizer.transcribe(audio,{signal})` returning `{recognizedText, uncertain}`, `voice.speak(text,{signal})` and `voice.stop()`. Handsfree additionally needs `vad.createSession({sampleRate,signal})` returning `{process(samples,{sampleRate,signal}), dispose?}`; its result is a probability from zero to one. The provider must check its own revision/ownership and cancel stale adapter results. Recognition receives mono Float32 PCM at 16 kHz, native capture sample rate, duration and a native-rate WAV Blob. Omitting explicit `uncertain:false` always requests learner review.

The same-origin AudioWorklet collects actual microphone PCM via getUserMedia, with a 60-second capture bound and a 30-second utterance bound. A level meter is not treated as voice detection. Only the supplied local VAD adapter segments handsfree utterances; bounded serial detection fails closed if it cannot keep up. The microphone stops before recognition, message generation and partner voice playback. Handsfree listening resumes after voice completion only; uncertain recognition requires review. Backgrounding, page termination, cancellation and disposal stop capture/playback, discard temporary audio and never restart listening automatically. The host must dispose its session before switching thread/profile/provider. This is alternating conversation, without a spoken barge-in claim.

Public actions are `startManual({replaceDraft?})`, `stopRecording()`, `edit(text)`, `confirm()`, `send()`, `startHandsfree({replaceDraft?})`, `retryReply()`, `restoreDraft()`, `replay()`, `saveRecording({consentAt})`, `pause()` and `dispose()`. Existing unsent text blocks recording until an explicit replacement choice. The snapshot includes state/mode/active, the editable draft, error, temporary-audio availability, a committed source turn identity and adapter readiness. Save Recording is available only after a learner turn has committed. It alone calls repository.saveRecording and requires an explicit consent timestamp. No Blob/audio buffer enters the draft journal or automatic save path. Replay uses a temporary local object URL and revokes it on completion, interruption or disposal. A reloaded transcript has no retained audio.

The controller Send contract is `{committed, turnId, reply, error}`; `reply` is the actual committed partner turn. A committed learner turn with missing/failed generation clears the transcript submission and enters `reply-needed`; Retry calls controller.reply alone. It cannot resend the learner turn. Recognition text, uncertainty, transcript edits and selected help are copied into draft and message input provenance; editing preserves the original recognizer text. Independent generation/teaching validation remains the service’s responsibility, rather than an audio adapter’s assertion.

The isolated unit suite passes eleven new lifecycle/data-safety cases plus the thirty earlier service cases. [The browser transport report](ai-speech-browser-audit.json) records actual Chrome getUserMedia/AudioWorklet capture from a synthetic microphone WAV: 44.1 kHz capture, 16 kHz recognition PCM, correct native-rate WAV framing, microphone shutdown, segmentation with an explicitly test-only detector, manual review/edit/send and actual temporary local replay. Neither Stop nor Send saved a recording; only the explicit Save choice did. These tests inject synthetic recognition/voice and make no Italian recognition, voice pronunciation, real human microphone, installed PWA, physical iPhone or production readiness claim. WebKit microphone permission/capture and human/device speech quality remain to be measured.
