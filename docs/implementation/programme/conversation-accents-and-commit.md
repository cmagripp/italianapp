# Conversation spelling and commit boundary

Development integration following `dcf2afa`. This implements the bounded spelling and transaction design; it does not enable a production conversation provider or supply a production contextual language checker.

## Behavior

The controller sends the saved message identity, revision, original/submitted/display text, input provenance and submission policy to the shared AI service. The service keeps its immutable original request for cancellation/currentness checks. An optional installed spelling adapter may propose an accent-only candidate before grounding or generation. A separate validator requires the shared accent comparison, exact case-sensitive accent-fold equality, reviewed source forms and independent contextual interpretation. It rejects word, person, negation, whitespace, punctuation and case rewrites. Ambiguous interpretation abstains; a missing adapter or historical submission policy leaves the message unchanged and allows ordinary generation to continue.

A verified strict-off candidate changes the same learner bubble and its partner reply in one IndexedDB transaction. The original and submitted text and saved policy remain unchanged. The source gains an explicit `accent-restoration` history entry and revision; prior lexical selections are not silently rebound to different displayed words. Correction references target the actual final source revision. No learning event, completion, review result or XP is generated by this spelling operation.

With strict accents on, the learner message is unchanged. The partner stores the source-bound historical spelling receipt; the view shows “A spelling note” on that learner bubble. Its selected meaning and personal notes retain their source revision. Later genuine edits make the note historical. The check always uses the setting saved when Send was pressed, even if Settings changes while it is pending. Confirmed or edited speech remains recognition/mixed origin and receives no typed-spelling penalty in this bounded version.

Receipts are deeply frozen and privately branded in the validator. Storage rechecks the brand against the exact live owner/thread/source revision and learner descriptor. Copies, imports and JSON are historical data, never authority to rewrite another message. Identical committed reply retries return the existing turn without a second source change. Historical notes use escaped message markup and are gathered once per render rather than scanning the entire transcript for every bubble.

## Reproduced cancellation defect and correction

The earlier actual-controller tests demonstrated that provider replacement after response validation could persist an old provider's reply, and cancellation after transaction creation could suppress the callback but still save the partner. The frozen pre-fix evidence remains in `ai-conversation-commit-boundary-before-{chromium,webkit}.json`.

The controller now owns provider-change cancellation. Each reply captures the provider revision and request generation and carries an AbortSignal and request guard into both generation-token creation and final storage. The repository checks these before/after opening IndexedDB, before every operation, after reads and before completion, and synchronously aborts an active transaction on cancellation. A provider switch, newer source or cancelled request cannot partially restore accents or append a stale partner before commit. A completed transaction is the durability boundary: later cancellation cannot undo an already committed message, but stale UI/audio publication is suppressed.

## Evidence and limits

- `tests/ai-input-spelling.test.mjs`: 22 policy/service checks, including NFC, uppercase, homographs, protected names, malformed/unreviewed sources, source-registry changes, cloned authority, legacy input and speech attribution. These use declared test registries and interpretation callbacks.
- `tests/conversation-accents-e2e.mjs`: nineteen actual UI/controller/repository checks in Chromium and WebKit. Covers in-bubble restoration, reload, original preservation, saved strictness, confirmed speech, quota/cancellation rollback after the source write, forged/stale/wrong-owner receipts, chosen-meaning/personal-note preservation, final correction revisions, idempotent retry and import history.
- `tests/conversation-commit-boundary-e2e.mjs`: seven timing boundaries and two noncooperative-provider cleanup cases per engine; cancellation settles the request and late work cannot commit or clear a newer retry.
- Eleven imported-note cases include valid strict/current/historical controls and altered originals, submitted text, policy, provenance, effective text and zero-accent differences. Only structurally consistent source-bound history is displayed.
- Seven summary checks include historical confirmed/mixed speech: accent spelling alone is not recorded as a learner mistake.
- Existing WebKit conversation player, storage and speech UI suites also pass after the controller/transaction integration.

No installed production registry, successful model, native educator review, physical-device runtime qualification or combined speech/model endurance is claimed. Recognition-origin spelling remains conservative until reliable character-level edit attribution is implemented. The full programme and production release gates remain open.
