# Phase 7 legacy retirement audit

Read-only audit, 3 October 2026. This is a proposed next slice, not an implementation or release gate closure. The [roadmap](../../IMPLEMENTATION-ROADMAP-2026-10-03.md#9-phase-7-validates-and-releases-the-complete-update) requires replacement coverage and imported-session compatibility before retiring old dispatchers, players or caches. The [source-bound inventory](phase-7-retirement-audit.json) records the inspected files, measured distribution sizes and exact current activation reproduction. No runtime, shell, index, asset or learner data was changed by this audit.

## Bounded next slice

1. Harden the supported imported Journey shape first. `compatible()` accepts an empty `journey.variants` map with a valid selected independent question. After assisted success, `recordJourneyAttempt()` directly assigns `j.variants[event.objectiveId].independent`; the missing entry throws after the canonical event can already be recorded. Initialise only that selected target's normal `{guided:0, independent:0, repair:0}` counter before the existing rewind assignment. Preserve existing counters, question identity, draft/feedback, assistance and evidence. Cover direct import/replay, canonical assisted event, Continue/reload and no duplicate event/XP. Coordinate this narrow `journey.js` change with curriculum's form-only revision work; it is a compatibility repair, not retirement.
2. Preserve the exact new pack namespace across a shell update. `js/ai/packs.js` stores the verified active pointer in `parola-ai-pack-v1:state` and assets in `parola-ai-pack-v1:<id>:<revision>`. Current `sw.js` activation deletes both. The exact handler, executed read-only against a synthetic cache inventory, deletes these names while preserving the old fit/assistant/WebLLM caches. Add the scoped pack prefix to preservation and test a verified synthetic installed pack/state through an actual worker update and cold offline reopen; assert unrelated old shell deletion, unchanged learner records, exact assets and working removal/repair. This does not establish real model quality or production provider readiness.
3. Retire the inactive fit scorer's site distribution after explicit old-client tests. It has no application caller: runtime references are confined to `js/learning/fit-scorer.js` and its worker. It remains required by the shell checker, build validation and check/deploy CI despite the product no longer using its advice. The assembled site still publishes 84,013,164 bytes across its two modules, six model files and two ONNX Runtime files. Preserve investigations, hashes and license notices in a source-only archive/dev area. Remove the runtime module/worker from the shell/distribution; exclude the exact `models/fit-scorer` and `vendor/ort` paths; update the build/check/CI assertions to prove absence and retained compatibility. Do not broadly remove `models`, `vendor`, worker handling or WebLLM caches. No learner data or stored advice should be rewritten.

The third item needs an already-open previous-client update fixture before integration: current lessons must make no scorer/model/runtime requests; a retained saved Workshop result must remain byte-exact and resumable; an old client with an installed scorer cache must either retain compatible cached operation or fail openly without losing its draft/history; an interrupted optional install must not be reported complete. Preserve intentionally compatible old caches until the worker activation contract handles this case. A dead import search alone does not prove old-client safety.

## Dormant old reply selector

The optional `assistant.js` selector remains dynamically imported by Workshop landing/player. Its trigger requires at least two `when:'*'` reactions in a dialogue turn. Across the current four Workshop packs, 21 lessons and 140 dialogue turns, zero turns meet this condition. The landing correctly disables the experimental switch, but still imports its module to show tool state. The new validated assistance service is a separate, conditional path.

A later narrow slice can remove the disabled selector row, eager tool-state refresh and unreachable candidate-selection hook, preserving authored reactions and already saved transcript/result/history exactly. Retain model investigations/redistribution notices outside the site. Do not identify WebLLM's shared `webllm/` caches as disposable merely because this selector is unused: the new provider investigation uses the same runtime family, and previous open clients may still hold its leases. This audit does not approve either the old model or a new production model.
